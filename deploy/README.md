# deploy/ — offline bundle packaging

Reproducibly builds the **self-contained, offline "unzip and run" bundle** of Edara
(the production build + a bundled Node runtime). Run it on a machine **with internet**;
the produced zip runs on the target with **no internet, no Node install, no `npm install`**.

## Usage

```bash
# Windows x64 (default), fresh database:
deploy/build-offline-bundle.sh

# Include the current server/data/edara.db instead of a fresh one:
deploy/build-offline-bundle.sh --with-db

# Other targets / Node version / output path:
deploy/build-offline-bundle.sh --target linux-x64
deploy/build-offline-bundle.sh --target win-arm64 --node v24.5.0 --out /tmp/edara.zip
```

Output defaults to `deploy/dist/edara-offline-<target>.zip` (git-ignored).

## What it does

1. Builds client + server (`npm run build`).
2. Installs **production-only** server deps (`npm ci --omit=dev`) and strips Unix
   `.bin` symlinks (so Windows can extract cleanly).
3. Downloads + caches a Node runtime for the target OS/arch (`deploy/.cache/`).
4. Assembles `node/`, `server/{dist,node_modules,public,src/db/schema.sql,package.json,.env}`,
   the launcher (`start.bat`/`start.sh`), and the Arabic run guide.
5. Zips and verifies (integrity + zero symlinks).

## Committed vs generated

- **Committed (source of truth):** `build-offline-bundle.sh`, `templates/`.
- **Generated (git-ignored):** `dist/` (zips) and `.cache/` (Node runtimes).

Deliberately **not** committed anywhere: the bundle's `node.exe` (per-OS binary),
`server/.env` (contains a secret), and build outputs (`dist/`, `public/`) — they're
regenerated by this script.

## Requirements (build machine)

`bash`, `node`, `npm`, `curl`, `zip`, and `unzip` (Windows targets) or `tar` (Linux targets).
