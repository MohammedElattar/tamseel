٢) الشاشات المرجعية

  • ملخص بيانات الضابط (image3–6): تبويبات — صورة الضابط وزوجته · الصورة العائلية · الوظائف السابقة (الرتبة/الوحدة/الوظيفة/من/إلى/المدة، الصفوف الخضراء = مميّزة) · تقارير الكفاءة (المتوسط + الفترات والدرجات). موجودة أصلاً كـ OfficerCvScreen ونعيد استخدامها.
  • نتيجة تقييم مسير الخدمة (image2.1): جدول مكوّنات المرحلة ٢ (الوظائف/التأهيل/الكفاءة/التشكيلات/الأوسمة/البعثات/الجزاءات) + الحد الأقصى ١٠٥٠ = ٧٨٠/١٠٥٠ = ٧٤٫٢٩٪. تُعرض كنافذة مرجعية للعضو.
  • أعلى تأهيل عسكري / مدني: يظهران بجانب البطاقة (من بيانات الضابط المستوردة).

٣) تغييرات نموذج البيانات

  • جدول جديد member_item_scores (committee_id, user_id, officer_id, item_id, score) — درجة كل عضو لكل بند.
  • القرار (تصدق/لا يتصدق) — للقائد ونائبه فقط — يُخزَّن في member_votes.user_opinion (١ = تصدق، ٠ = لا يتصدق) ويصبح القرار النهائي للضابط.
  • مسير الخدمة (بند kind=computed) يأخذ درجته من officer_service_score.pct (المرحلة ٢) — للقراءة، نفس القيمة لكل الأعضاء.
  • متوسط تقييم العضو = Σ درجاته ÷ Σ الحدود القصوى × ١٠٠. النتيجة النهائية للضابط = متوسط متوسطات الأعضاء + أغلبية «تصدق».
  • API جديد: POST /evaluations/scores (حفظ الدرجات) وGET /evaluations/current يُرجّع البنود + درجات العضو + مسير الخدمة.

٤) سير العمل

  1. المسؤول يعرض الضابط (المرحلة ٥) → تظهر بطاقته للأعضاء تلقائياً.
  2. كل عضو يُدخل درجات البنود اليدوية (مسير الخدمة مملوء) ويضغط «حفظ التقييم».
  3. القائد (ونائبه) يراجع متوسط اللجنة ويختار «تصدق» أو «لا يتصدق» — القرار النهائي.
  4. القائد ينتقل للتالي بعد اكتمال درجات كل الأعضاء (نفس بوابة التالي الحالية).

أسئلة قبل التنفيذ

أ) من يُدخل الدرجات ومن يقرر؟ تم الحسم

كل الأعضاء (بما فيهم القائد) يُدخلون درجات البنود ويحفظونها؛ والقرار «تصدق / لا يتصدق» للقائد ونائبه فقط.

ب) خيارات قرار القائد تم الحسم

تصدق / لا يتصدق فقط.

ج) «متوسط التقييم النهائي» تم الحسم

نسبة كل عضو = Σ درجاته ÷ Σ الحدود القصوى × ١٠٠.
